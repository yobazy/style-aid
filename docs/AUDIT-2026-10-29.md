# Style Aid audit, 2026-10-29

## What the app is

Style Aid is a single-page wardrobe planner (React 19 + TypeScript + Vite 8). You log closet pieces, build outfits ("looks") against scenarios (work, going out, weekend, date night, travel), and keep a wishlist where each item is tied to the looks it would complete. Everything lives in the browser's `localStorage` (`style-aid-state-v2`, with a migration from `v1`). There is no backend and no auth. The only server code is a Vite dev/preview middleware, `vite.plugins/productImport.ts`, which serves `GET /api/import-product?url=...` to scrape a product page's Open Graph tags.

How it runs: `npm install`, `npm run dev` (Vite on 5173), `npm run build`, `npm run lint`. Before this run there were no tests.

## Findings, ranked

Severity: **High** = breaks the app or loses data, **Medium** = wrong output or a real exposure, **Low** = rough edge.

### Bugs

| # | Sev | Finding | Evidence |
|---|-----|---------|----------|
| B1 | High | Saving a large photo crashes the whole app. `saveState` calls `localStorage.setItem` with no `try/catch`, inside a `useEffect`. Photos are stored as full-size base64 data URLs, so one phone photo (3 to 5 MB) can exceed the ~5 MB quota; the `QuotaExceededError` is uncaught and React 19 unmounts the root (blank page). | `src/lib/storage.ts` `saveState`, `src/App.tsx` effect |
| B2 | Medium | Wishlist cards show "Est. spend $NaN" when a price has a symbol or comma (`$295`, `1,200`). The card uses `Number(...)` while the totals use `parsePrice`. | Confirmed in the browser (desktop and phone) |
| B3 | Medium | Re-adding a wishlist entry with the same title and category (for example tapping "Add to wishlist" on the same gap twice) silently overwrites the existing entry: brand, retailer, prices, link and notes are wiped to empty, status resets to Researching, and a replacement entry loses its replacement flag (then gets duplicated by the replacement sync). | `src/App.tsx` `upsertWishlistItem` spreads `...item` over `existing` |
| B4 | Medium | Imported prices are misread: `1,299.00` becomes `129`, `49,99` becomes `4999`. | `vite.plugins/productImport.ts` `sanitizePrice` |
| B5 | Medium | Category guessing on import misses plurals ("White Sneakers", "Ankle Boots", "Straight Jeans", "Wide Trousers", "Gold Earrings" get no category) and sends "Short Sleeve Shirt" to Bottoms. Product titles are usually plural. | `src/lib/productImport.ts` `categoryMatchers` |
| B6 | Medium | Insights "Best next spend" lists the first five wishlist entries in storage order, not by usefulness, and both it and Home "Most useful next buys" include items already bought. | `src/components/InsightsView.tsx`, `src/App.tsx` `topWishlist` |
| B7 | Medium | Look builder: pieces you picked stay selected after you switch scenario or season, even though they are no longer shown. They still count toward "% complete" and are saved into the look, invisibly. | `src/components/LooksView.tsx` |
| B8 | Low | A failed photo read (`FileReader` error) is an unhandled promise rejection; nothing tells the user. | `src/components/ClosetView.tsx` `handleImageChange` |

### Security

| # | Sev | Finding | Evidence |
|---|-----|---------|----------|
| S1 | Medium | SSRF in the import middleware. `/api/import-product` fetches any URL, including `localhost`, `127.0.0.1`, LAN and link-local addresses, with no timeout and no size cap. On `pc` it happily fetched the local Ollama port. The response has no CORS header, so another website can only fire blind requests through it, but anyone who can reach the dev or preview server (for example `vite --host` on a shared network) can use it to read internal pages. It also follows redirects. | `curl "http://localhost:5391/api/import-product?url=http://localhost:11434/"` returned a JSON result |
| S2 | Medium | `npm audit`: 9 advisories (7 high), all in dev tooling. Most relevant: Vite 8.0.10 "Cross origin script execution through Vite custom middleware" (GHSA-9jrq-w75r-8gcw) and `server.fs` bypasses. All fixable by patch/minor bumps. | `npm audit` |
| S3 | Low | `productUrl` (user typed or imported) goes straight into `<a href>`. React 19 blocks `javascript:` URLs and the data is only the user's own, so this is low, but non-http links are still accepted. | `WishlistView.tsx` |
| S4 | Info | No secrets in the tree or history. All data is local to the browser; nothing leaves the device except the import request. Photos sit unencrypted in `localStorage`, which is normal for a local-only app. | `git log --all --stat` |

### Accessibility basics

| # | Sev | Finding |
|---|-----|---------|
| A1 | Medium | Toggle chips (scenarios, intended looks, "Can style with"), the piece picker cards and the tab bar do not expose their state: no `aria-pressed` / `aria-current`. A screen reader user cannot tell what is selected. |
| A2 | Low | The custom focus ring is applied on `:hover` (mouse), not on `:focus-visible`, so keyboard users get only the browser default ring on buttons and links. |
| A3 | Low | The Formality slider shows no value; it has a label but no visible number. |
| A4 | Low | Look collages draw black pieces as near-black tiles on a near-black card, so dark outfits look empty (see `before-desktop-home.png`). |
| A5 | Low | Tabs and eyebrow labels are all caps with wide letter spacing (`text-transform: uppercase`), which is harder to read and goes against the house copy rule (sentence case). Design call, listed as a question. |
| A6 | Medium | Closet pieces without a photo show their color name in near-black text on the color swatch, so black, navy, brown and burgundy pieces have an unreadable label (and the empty "Add a color and photo" stage is black on black). |

### Performance

| # | Sev | Finding |
|---|-----|---------|
| P1 | Medium | Photos are stored at full resolution as base64 in `localStorage`, and the whole state is re-serialized on every change. This is what causes B1 and will make every keystroke slower as the closet grows. Downscaling photos on upload (for example to 800 px JPEG) would fix both; that is a behavior change, so it is listed as a question. |
| P2 | Info | Bundle is small (71 kB gzip). Lighthouse-level work is not needed yet. |
